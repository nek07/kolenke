# kolenke: автоотклики и рассылка резюме

Отклики на hh (вручную или на автопилоте), мониторинг Хабр Карьеры и Enbek, письма компаниям с вашего Gmail,
воронка после отклика и база ответов для HR-роботов. Всё работает на вашем компьютере: hh видит IP вашей сети,
а сессия hh, пароль Gmail и база вакансий никуда не уходят.

## Запуск

Двойной клик по `start.command`. Откроется http://127.0.0.1:3000.
Первый запуск сам установит зависимости (нужны Python 3.12+ и Node.js 20.9+).

Вручную, в двух терминалах:

```bash
cd backend  && ../.venv/bin/uvicorn kolenke.main:app --host 127.0.0.1 --port 8765
cd frontend && npm run build && npm run start
```

## Как пользоваться

1. **Настройки**: имя, телефон, должность, файл резюме (PDF), Gmail и пароль приложения
   (myaccount.google.com → Безопасность → Пароли приложений).
2. **HeadHunter**: «Войти в hh» → войдите в окне браузера. Выберите резюме, «Найти вакансии»,
   пролистайте карточки «Откликнуться / Пропустить» и нажмите «Откликнуться».
   Главная цифра на «Сегодня» — **приглашения за неделю**; «не больше откликов в день» только бережёт аккаунт от капчи.
3. **Автопилот**: «С проверкой» (находит свежие вакансии и присылает уведомление, откликаетесь вы) или «Полностью сам».
4. **Воронка**: что происходит после отклика. Карточки двигают ответы с hh и вы сами, напоминания приходят за сутки и за час.
5. **Письма компаниям**: CSV/Excel с колонками «компания; email; должность» → «В очередь» → «Отправить очередь».
6. **Другие сайты**: Хабр Карьера и Enbek с зарплатой, городом и контактами; почту можно отправить в «Письма компаниям».

Поиск по всему (вакансии, чаты, письма): ⌘K или `/`.

## Устройство

```
backend/            FastAPI, только JSON API на 127.0.0.1:8765 (документация: /docs)
  kolenke/
    main.py         create_app(): lifespan (миграции, планировщик), middleware, роутеры
    config.py       настройки запуска из переменных KOLENKE_* (папка данных, порт)
    api/            роутеры по разделам + защита «только с этого компьютера»
    schemas/        Pydantic-модели запросов и ответов, Enum статусов, типизированные настройки
    services/       бизнес-логика без HTTP: фильтры, воронка, база ответов, почта, импорт, сводка
    db/             SQLite: подключение, миграции (PRAGMA user_version), репозитории — весь SQL здесь
    sources/        браузерная автоматизация: hh/ (вход, поиск, отклики, чаты, статусы) и boards/ (Хабр, Enbek)
    workers/        фоновые задачи по одной, автопилот, планировщик
  tests/
frontend/           Next.js (App Router) + TypeScript на 127.0.0.1:3000
  src/app/          маршруты: /, /hh, /pipeline, /chats, /mail, /sites, /answers, /stats, /settings
  src/features/     экраны
  src/components/   общие компоненты; ui/ — shadcn/ui
  src/api/          типизированный клиент; schema.d.ts генерируется из OpenAPI бэкенда
  e2e/              тесты Playwright
data/               ваши данные (в git не попадают): база, сессия hh, резюме, скриншоты ошибок
```

Страница ходит в API через прокси Next (`/api/*` → FastAPI), поэтому для браузера это один адрес и CORS не нужен.
Бэкенд отвечает только запросам с localhost и требует заголовок `X-JobBot` для изменений: чужие сайты не могут
ничего сделать от вашего имени.

**Новый сайт с вакансиями** — один модуль в `backend/kolenke/sources/boards/` с классом по протоколу `Board`
(`search` и `details`) и строка в `REGISTRY`. Фильтры, сохранение, история и интерфейс подхватят его сами.

**Изменение схемы базы** — новая функция в конец `MIGRATIONS` в `backend/kolenke/db/migrations.py`.
Уже выпущенные миграции не меняются.

**Изменение API** — после правки схем обновите типы фронта: `cd frontend && npm run api:types`.
TypeScript покажет всё, что нужно поправить на странице.

## Разработка

```bash
.venv/bin/pip install -e "backend[dev]"            # бэкенд как пакет + pytest, ruff
cd frontend && npm ci

cd backend  && ../.venv/bin/uvicorn kolenke.main:app --port 8765 --reload
cd frontend && npm run dev                          # http://localhost:3000, перезагрузка на лету
```

## Тесты

```bash
cd backend  && ../.venv/bin/python -m pytest && ../.venv/bin/ruff check .
cd frontend && npm run check                         # типы, eslint, prettier
cd frontend && npm run test:e2e                      # Playwright: свой бэкенд на временной базе + сборка страницы
```

Тесты работают на временной базе (`KOLENKE_DATA_DIR`), без hh, Gmail и уведомлений. Действия на самом hh
(отклик, письмо, чат) проверяются на логике вокруг браузера, а не на живом сайте: они зависят от вёрстки hh.
